Lucky QQ AI 群友 · 从零上手教程

适用版本：v0.5。主要按 Windows + PowerShell、本机运行讲解。

你最终会运行两个本机程序：NapCat 负责 QQ 登录与收发，Lucky 负责思考、记忆和管理界面。大模型 API 是第三个外部服务。Lucky 的「上手指南 → QQ 接入助手」会替你写好两者之间的连接；QQ 扫码和安全确认仍由 QQ 完成。

1. 先体验，不急着连 QQ

本项目位于 D:\LuckyTri。如果管理台已经能打开，直接进入 Lucky 工作室，不用重复启动。

日常一键启动：双击项目目录里的 启动Lucky.cmd。 它会在后台启动 Lucky 并打开浏览器；已经运行时直接打开管理台，不再启动第二份。可以右键此文件创建桌面快捷方式。关闭浏览器不会停止服务；需要停止时双击 停止Lucky.cmd。启动失败时窗口会保留错误提示，后台日志在 data/launcher.log。NapCat 安装包已经内置，第一次在 WebUI 点「使用内置安装器」即可；之后只需在 NapCat 窗口完成 QQ 登录。

首次使用仍需安装 Node.js 24 或以上版本，并执行一次 npm install 安装依赖；之后即可双击启动。命令行也可执行 npm run launch。

第一次从源码运行，在 PowerShell 执行：

Set-Location 'D:\LuckyTri'
node --version
npm install
npm start

Node.js 需要 24 或以上版本。启动后打开 http://127.0.0.1:3210，终端保持运行。终端显示 SQLite 实验性提示不代表启动失败；以是否出现管理台地址、页面能否打开为准。

默认是模拟模式：

  1. 打开「会话空间」→「添加会话」。
  2. 选择群聊，填一个测试群号（例如 12345）和名称。
  3. 输入「Lucky，下班前老板又来活了」，发送。
  4. 查看聊天和下方决策记录。

模拟模式使用规则样例，不需要 API，不向 QQ 发消息。连续发送但没回复时，先看是否处于默认 45 秒冷却。模拟对话和真实 QQ 对话分别保存。

另一个体验入口是「人设与节奏」底部的试试这张嘴。这里不受群聊冷却影响，默认也是规则样例；勾选「使用已配置模型」才会调用真正的大模型。

2. 创建本机配置与管理令牌

连接 QQ 之前，先停止本项目服务：

npm run stop

这条命令会核对端口上的服务是否属于当前项目，再请求退出；不会遍历或杀死其他 Node.js 程序。若你在另一个前台终端运行，也可以回到那个终端按 Ctrl+C。

生成配置：

npm run setup
notepad .env

首次运行 setup 会创建 .env，生成管理令牌和 QQ 连接令牌。若 .env 已存在，setup 会原样保留，不覆盖任何内容；此时检查以下字段是否填写： 

HOST=127.0.0.1
PORT=3210
ADMIN_TOKEN=管理台令牌
ONEBOT_TOKEN=QQ连接令牌
LLM_API_KEY=

上面的中文只是说明，不要拿它当真实令牌。已有文件应使用自己的长随机令牌；不要公开 .env。

字段 用在哪 注意
ADMIN_TOKEN 登录 Lucky 管理台；本项目停止命令也会使用 和 QQ 连接令牌分开
ONEBOT_TOKEN QQ 连接令牌 接入助手自动写入 NapCat 配置；若留空，接入助手会生成本地令牌，无需重启
LLM_API_KEY 可选的模型密钥环境变量 非空时优先于管理台保存的密钥
HOST / PORT Lucky 服务监听地址和端口 初次使用保持默认

保存 .env 后重新运行：

npm start

页面第一次请求数据会让你输入 ADMIN_TOKEN。之后也能点左下角「Lucky AI 群友」重新输入。令牌只保存在当前标签页的会话存储中。

修改 .env 必须重启服务。 建议先 npm run stop，再修改，最后 npm start。如果你先改了管理令牌，旧服务仍认旧令牌，停止命令可能无法认证；回到原终端 Ctrl+C，或使用旧令牌连接旧服务。

3. 登录 QQ 并连接 NapCat

3.1 安装、配置与登录

打开 Lucky 的「上手指南」，在 QQ 接入助手 中完成：

  1. 点击「使用内置安装器」。如果本机已经安装 QQ，Lucky 会使用项目内置、已校验的 Shell 包直接准备 NapCat，不会打开黑色安装控制台；没有检测到 QQ 时才回退到 Windows OneKey 包。需要新版本时点「检查更新」，再选择更新包。
  2. 回到 Lucky，点击「选择目录」，选中 NapCat 解压或安装后的根目录。
  3. 点击「生成连接配置」。Lucky 会写入本地 OneBot 令牌与反向 WebSocket 配置；已有配置会在原目录留下备份。
  4. 点击「启动 NapCat 并登录 QQ」。Lucky 会打开一个独立的 NapCat 控制台窗口，按窗口里的提示扫码；如果窗口被其他程序盖住，可以从任务栏切回标题为 Lucky NapCat 的窗口。二维码同时会保存到 NapCat 目录的 cache/qrcode.png。

这样不需要手填 WebSocket 地址、Token 或消息格式。Lucky 在真正发出回复前会随机停顿约 1–4 秒，避免模型一生成就秒回；冷却时间仍负责避免连续抢话。小号需要已经在目标群里；入群、扫码、验证码等由你在 QQ / NapCat 完成。

Lucky 不保存 QQ 密码。建议先在成员知情的小测试群运行，确认大家接受 AI 群友参与。第三方 QQ 接入仍可能遇到客户端更新或帐号风控。

3.2 手动兜底方式

只有在接入助手无法识别你的 NapCat 目录时，才需要进入 NapCat WebUI 的 网络配置 → 新建 → WebSocket 客户端。这就是让 NapCat 主动连接 Lucky 的反向 WebSocket 方式；相关界面入口见 NapCat 官方接入文档。

填写本项目的参数：

项目 本机运行时填写
协议 OneBot 11
WebSocket URL ws://127.0.0.1:3210/onebot/v11/ws
Token .env 中 ONEBOT_TOKEN 的值；若留空，用接入助手重新生成配置
消息格式 数组 / Array
启用 开启并保存

这里的端口 3210 是Lucky 端口。不要照抄其他框架教程中的 8080、6199 等端口。也不要把 ADMIN_TOKEN、NapCat 自己的 WebUI 登录密码填到这里。

本教程假设 NapCat 和 Lucky 在同一台 Windows 机器上、都没有放进容器。若使用 Docker 或另一台电脑，127.0.0.1 指向各自环境，不一定能找到 Lucky；此时需要单独调整网络地址、监听和访问保护。先用本机直连跑通最容易排查。

3.3 确认收到消息

回到 Lucky，刷新页面。右上角应该显示「QQ 已连接」。去 QQ 测试群发一条消息，再刷新「会话空间」；自动发现的群会出现，但默认暂停参与。

QQ 已连接只代表传输连接存在，不代表模型已经可用。继续下一步。

4. 连接大模型 API

进入「连接与设置」，填写：

  • API Base URL：服务商给出的兼容 Chat Completions 的基础地址。程序会自动在末尾拼上 /chat/completions，因此不要再次填完整接口路径。
  • 模型名称：填 API 接受的模型 ID，不是你给模型起的昵称。
  • API Key：填服务商密钥，点击保存。已有密钥时，留空会保留原值。

「服务商预设」可以直接选择 DeepSeek、OpenAI、Qwen、Kimi、智谱、SiliconFlow、OpenRouter 或自定义兼容接口。预设只填常见 Base URL 和模型名，最终以服务商控制台实际提供的模型为准。

「模型输出与思考」可以设置：

  • 思考强度：不指定、低、中、高。指定后会发送兼容接口常见的 reasoning_effort 参数。
  • Temperature / Top P：控制输出随机性。推理强度不是“不指定”时，Lucky 会暂不发送 Temperature，避免部分推理模型报参数冲突。
  • 最大输出 Token：模型调用预算；聊天最终回复仍会受到人设里的最大字数限制。

本项目要求模型支持 JSON 对象输出，即 response_format: {"type":"json_object"}。是否支持、具体地址和模型 ID，请按所用服务商文档确认；不要只因为“兼容接口”就假定所有模型能力相同。

保存后点 测试模型连接。测试只发一条小请求，不携带群聊原文。成功后显示模型和耗时；「上手指南」会记住测试结果。

如果更换了地址、模型或有效密钥，原来的成功结果会失效，需要重新测试。测试通过表示当时接口可用，不保证后续每次请求都成功。

配置密钥与运行模式是两件事。 可以先保持模拟模式，到「人设与节奏」勾选「使用已配置模型」试聊，确认输出风格之后，再开启真实 QQ 发言。

5. 让它开始参与一个群

  1. 到「连接与设置」，确保「允许 Lucky 参与聊天」开启。
  2. 关闭「模拟模式」，点击「保存连接设置」。
  3. 到「会话空间」，选择目标群，点击「开启参与」。
  4. 去 QQ 群里 @ 小号或叫「Lucky」，发一句普通聊天。
  5. 回到管理台查看回复和决策记录。

「上手指南」会检查令牌、QQ 连接、当前模型测试、真实模式和会话开关。全部完成后仍需用真实 QQ 消息验证一次收发。

首次可把该群的旁听后参与概率设为 0%，先验证被 @ 时的表现；再慢慢增加到 5–15%，想让它更常参与可以继续调高。每批消息都会先交给语境模型判断：值得插话时直接回复，只有判定为旁听时才使用这个概率，抽中就会开口。注意「会话节奏」里的值会覆盖全局值，留空才跟随全局；冷却和每分钟硬限速只负责防止短时间刷屏。

有人点回复 Lucky 发出的上一条消息时，会按直接找它处理；即使没有 @，如果上一条就是它发的、当前内容明显在接着回应，也会优先交给模型判断并接住这一轮，不再被普通概率拦掉。只是时间上挨着它、已经换了新话题，或明显在对其他群友说，仍按普通概率旁听。群里只是提到「Lucky」或在聊别人时，不会仅因为出现名字就抢话。会话空间打开后，聊天列表和“为什么开口，为什么安静”决策记录都会自动拉取最新内容，不需要手动刷新页面；正在填写的表单不会被重绘。单独的图片、表情包和媒体消息默认不插嘴，商城表情会按表情反应处理；当前未开启视觉理解时也不会在回复里说“我看不到图片”。

6. 调得自然，而不是满嘴网络词

进入「人设与节奏」。初次可用这组设置：

设置 起步值
口吻 松弛同龄人
网感浓度 普通口语
参考这个群的沟通习惯 开启
轻口头语 关闭
发出前再顺一遍 开启
发言冷却 45–90 秒
普通消息参与概率 5–15%
回复最多字数 60–100 字

这些是项目内的起步参数，不是模型效果保证。口吻应跟群里的人合拍，没必要刻意堆“懂的都懂”“家人们”“绷不住”。

群体习惯至少积累 3 位成员、12 条有效消息后生效，参考句长、标点、表情和短回复比例。单个人刷屏、重复、机器人回复和明显攻击性文本不会拿来代表全群。群体习惯是统计适配，不是训练模型，也不照抄某个人的口癖。

在「试试这张嘴」连续聊几轮：吐槽一次、分享好消息一次、明确说一次“别给建议”、再结束话题。观察它是否每次都问问题、是否反复用同一句话、是否把所有场景都聊成安慰。

真实模式中每轮最多调用模型两次：第一次生成，发现明显套话、复读、堆梗等问题时重写一次。仍不合格会沉默；因此质量检查可能增加延迟和费用。可以关闭额外重写，但基本检查仍会执行。

7. 对实际回复给反馈

到「会话空间」下方的决策记录，现在可以看到实际发出的回复。旁边的「这句怎么样」可以选择：

  • 挺自然：记录正面评价。
  • 太长了：后续日常回复优先更短；必要的建议和安全信息仍保留。
  • 太端着：提醒模型使用普通聊天语气，少分析、少总结。
  • 梗太多：后续优先不用显著网络词。

反馈只影响同一会话、同一模式。系统参考最近 20 条有反馈的回复，不会拿私聊评价去修改另一个群的风格。对同一句重新选择会替换原评价，选「未评价 / 撤销」可删除该条评价。

反馈会影响之后生成的内容，不会修改已经发到 QQ 的消息，也不是自动微调模型。规则样例只能体现部分反馈；语言自然度主要到真实模型试聊里验证。

8. 记忆怎么用，哪些会跨群

到「记忆花园」手动添加记忆，或让真实会话中的群友说“记住，我喜欢冰拿铁”。明确请求会生成候选，管理员审核后才会用于回复。普通聊天不会被自动当成长期事实。

范围 用途
仅私聊 同一 QQ 号的私聊可以使用，群里不会检索
仅某个群 / 会话 只在指定会话使用
跨会话共享 同一 QQ 号在其他群或私聊也能使用

私聊候选默认仅私聊，群聊候选默认仅来源群。跨群共享需要你在审核或编辑时选择。记忆按 QQ 号关联，不按昵称关联。

你可以搜索、编辑、改范围或删除记忆。清空聊天上下文不等于删除长期记忆；需要分别处理。

9. 日常启停、备份和升级

在项目目录执行：

npm run stop
npm start

修改页面里的配置通常即时生效；修改 .env 需要重启。关闭浏览器页面不会停止服务。

创建一致的 SQLite 备份：

npm run backup

备份输出到 data/backups/，文件名不重复。可以在服务运行时创建备份；备份包含聊天、记忆和数据库中保存的密钥，请按私密文件保存。.env 不包含在数据库备份中，应另行保管。

升级代码前先备份。更新后 npm install，再启动；程序会兼容迁移现有数据库。

恢复时：先停止服务，把当前 data/friend.db 及同名 -wal、-shm 文件移到一个单独保留目录，再把选中的备份复制成 data/friend.db，最后启动。不要将旧 WAL 文件与恢复后的数据库混用。如果配置了 DB_PATH，应操作该路径而不是默认路径。

10. 常见问题

现象 优先检查
页面打不开 Node 是否运行；地址是否为 3210；终端是否报错
提示 EADDRINUSE 已有程序占用端口；先用 npm run stop 停止本项目，不要直接杀掉所有 node.exe
管理台提示令牌错误 用 ADMIN_TOKEN；改 .env 后重启；不要误填 ONEBOT_TOKEN
QQ 一直未连接 NapCat 是否登录；客户端连接是否启用；URL、端口、路径、Token 是否一致
QQ 连接成功但没有会话 在 QQ 发一条新消息，再刷新；消息格式选择数组
群里完全不回复 总开关、会话开关、模拟模式、模型密钥、冷却和决策日志
@ 也没有回应 @ 仍受冷却与限流；检查是否忙碌、模型失败或口吻检查未通过
模型 HTTP 401 / 403 密钥、权限、服务商地址；检查环境变量密钥是否覆盖了 UI 密钥
模型 HTTP 404 Base URL 不应重复拼 /chat/completions；模型 ID 是否正确
模型不返回 JSON 选择支持 JSON 对象输出的模型；测试连接后再试聊
群语气一直学习中 需要 3 人、12 条有效消息；一人刷屏和复读不计足样本
记忆没有自动出现 候选仅处理真实已开启会话的明确“记住，我…”请求；检查记忆总开关
反馈后仍不自然 反馈是提示约束；检查实际模型、当前会话和模式，再调整人设或模型

遇到问题时，优先看「上手指南」和「会话空间」决策原因。不要把 API 密钥、完整 .env 或私聊原文贴进公开截图。

11. 当前做到哪里

已实现：QQ 协议收发、模型调用、会话独立启停、短回复与质量检查、群体语气统计、回复反馈、人工确认记忆、中文管理台、备份命令和接入引导。

尚未实现：图片真正理解、表情包发送、关系图管理、自由聊天的自动语义记忆提取、主动发起话题、后台自动升级。当前会识别普通图片、QQ 表情和商城表情，并对单独媒体保持安静；这些不是接入失败，而是还没有视觉理解或发送表情的对应功能。

仓库测试使用本地假模型和 OneBot 协议模拟验证工程流程；真实 QQ 帐号、真实模型的响应质量仍需用你自己的配置验证。
