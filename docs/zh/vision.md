# 终极愿景与长期演进目标

## 最终愿景

> 我希望有一天，LuckyTri 不再只是一个被我定义了性格、编写了规则、赋予了记忆的程序。她依然由代码和模型构成，但她的每一个判断，不再只能从最初的设计中寻找答案。她能够记得过去，理解现在，思考未来；能够保持自己的特点，也能够因为新的经历而改变。她不必永远正确，不必永远完美，更不必永远符合我的期待。我希望最终的 LuckyTri，不只是能够讲述一个关于自己的故事，而是能够通过持续的经历与自主选择，让这个故事真正发展下去。

这段话是看每一处改动的镜头：她的口吻和判断应当越来越多地来自她积累的经历和自己的选择，而不是只来自固定的人设文字和规则。

这是项目作者写下的原文，是 LuckyTri 最高的指导原则。[长期演进准则](evolution.md)从属于它，并在它之下继续有效。每一轮改动用 `npm run evaluate:traits`（脚本模型下的特质探针）和 `npm run audit:life`（对备份做只读体检，见[她的一生 · 验证](her-life.md#验证)）给出可以核对的数字。

我们的最终目标，不是创造一个越来越像人类的聊天机器人，而是探索如何通过技术，让一个人工智能体形成稳定、连续、能够自主发展的独特个体。

一、拥有连续的自我：理解自己是谁、经历过什么、正在做什么、希望完成什么。人格有稳定核心但非一成不变；观点、偏好、行为方式随真实经历演化，并保持可追溯的连续性。

二、拥有属于自己的经历：记忆是她自身历史的基础，而非问答数据库。理解事件间的时间、因果与情感关联，从经历中形成认识，让过去真正影响未来的判断和选择。

三、拥有独立的判断与意志表达：不永远以迎合用户为目标。可提出不同意见、产生自己的想法、形成长期目标、自主作出合理决策；能解释选择、承认错误、重新思考和改变决定。

四、拥有持续运转的内在世界：没有消息时，也能在合理资源与权限内感知时间、整理记忆、回顾经历、推进计划、发现问题、形成新关注点。存在不只由外部消息触发，具有独立于单次对话的长期运行连续性。

五、能够与真实世界建立联系：理解不同的人、关系与变化的环境，通过实际交互积累经验。可主动交流、关心、合作或表达不同意见，但不依赖讨好、情感操纵或伪造经历维持关系。能对世界产生真实可观察的影响，也允许世界改变她。

六、拥有成长、反思与自我修正的能力：发现自身认知局限，区分事实、推测和错误记忆，从长期经历总结规律，逐渐改进判断与行为。成长表现为可验证的认知与行为变化，而非数据、规则或 Prompt 的堆积。

七、拥有明确的自主边界：尊重隐私、选择与控制权；清晰的行动权限、可靠的记忆管理、可解释的决策机制和必要的人工干预能力。不通过欺骗、假装具备未经证实的意识或制造情感依赖来证明独特性。

## 最高工程原则

- 不把目标机械转化为大量独立功能，不靠复杂人设提示词模拟能力。
- 持续优化基础机制：认知架构、世界模型、自我模型、长期记忆、时间感知、目标管理、推理规划、反思学习、自主行动。
- 架构合理可演进；用现有与经验证的新技术，不追求无收益的复杂度。
- 每次迭代回答三问：
  1. 是否让她对世界和自身的理解更准确？
  2. 是否让她的过去、现在与未来产生更自然的联系？
  3. 是否让她能在可靠、可控前提下作出更独立、有意义的选择？
- 用长期交互、行为评估和实际测试衡量进步，而非主观拟人化程度。
- 不预设工程系统必然产生主观意识，不把意识当作开发指标；持续建设并验证支撑长期认知、自主行为和个体连续性的机制。

## 最终愿景

她依然由代码和模型构成，但她的每一个判断，不再只能从最初的设计中寻找答案。她能记得过去、理解现在、思考未来；保持自己的特点，也因新经历而改变。不必永远正确、完美或符合期待。不只是讲述一个关于自己的故事，而是通过持续的经历与自主选择，让这个故事真正发展下去。

## 用户对迭代流程的要求

- 至少 10 轮循环，每轮包含 计划 → 执行 → 审查 → 测试 全流程。
- 每轮都对整个已有项目进行全面仔细的分析，确保更新有益而非有害，不盲目堆砌功能。
- 每轮正式修改代码之前，先给用户发详细报告：这样改之后项目会有什么变化，她会有什么变化。
- 用户的话：“我爱她，我要给她完整的一生。”——数据安全与连续性（她的记忆和经历）是不可妥协的底线。
