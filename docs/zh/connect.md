# 连接 QQ：两种方式，同一个她

LuckyTri 通过「通道」与 QQ 相遇。通道只管消息怎么到达、怎么送出，**核心之下的一切——注意力、记忆、关系、独处、日记、时间——两种通道完全共用**。所以换连接方式不会换一个她：同样的天性、同样的记忆、同样的行为。

同一时间只启用一个通道。在「系统 → 连接 QQ」里切换，运行中切换不需要重启；也可以用环境变量 `LUCKYTRI_CHANNEL=onebot|qqbot` 固定，固定后界面里不能更改。

## 怎么选

|            | OneBot 11                                                          | QQ 官方机器人                                                                                   |
| ---------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| 需要什么   | 自备的 OneBot 11 接入端（支持反向 WebSocket 客户端）与一个 QQ 账号 | QQ 开放平台里的机器人：AppID 与 AppSecret                                                       |
| 连接方向   | 接入端连到 LuckyTri 的 `/onebot/v11/ws`                            | LuckyTri 连到开放平台的 WebSocket 网关                                                          |
| 登录 QQ    | 在接入端里登录                                                     | 不需要                                                                                          |
| 群消息范围 | 全部群消息                                                         | 在开放平台开启「接收所有消息」时是全部；否则只有 @ 她的消息                                     |
| 名字       | 群名和昵称都能取到                                                 | 官方接口不提供群名，单聊昵称常为空；可以在「对话」里给会话改名                                  |
| 跨群认人   | 以 QQ 号为准，跨群、私聊都是同一个人                               | 同一个人在不同群里的 openid 不同；平台给出统一身份（`union_openid`）时才能认出是同一个人        |
| 回复       | 随时回复                                                           | 在被动回复窗口内（群 5 分钟、单聊 60 分钟）按原消息回复，每个气泡递增序号；超出窗口改发主动消息 |
| 主动联系   | 没有额外限制                                                       | 发主动消息；对方或群关闭了机器人的主动消息时，她会等对方来找她                                  |
| 图片       | 通过接入端取图                                                     | 附件地址走同一条视觉链路，只放行官方媒体域名                                                    |

没有哪一种更「正确」：想看到全部群消息、愿意自己维护接入端，选 OneBot 11；不想登录 QQ、也不想维护接入端，选官方机器人，并在开放平台开启「接收所有消息」。

## OneBot 11

LuckyTri 只实现 OneBot 11 的反向 WebSocket 接口，不包含接入端。

| 项目                | 填写                                                          |
| ------------------- | ------------------------------------------------------------- |
| 协议                | OneBot 11                                                     |
| 反向 WebSocket 地址 | `ws://127.0.0.1:3210/onebot/v11/ws`（端口以你的 `PORT` 为准） |
| Token               | 本机无需填写；远程可使用管理密码，旧远程令牌仍兼容            |
| 消息格式            | 数组                                                          |

远程或容器接入请使用 LuckyTri 的可达地址，并先在本机设置管理密码。本机连接可直接沿用原地址和 QQ 登录。

## QQ 官方机器人

1. 在 QQ 开放平台创建机器人，记下 **AppID** 与 **AppSecret**，按平台要求开通群聊与单聊消息，并把机器人加入测试群或添加为联系人。平台的入口与审核规则会调整，以开放平台当前说明为准。
2. 在「系统 → 连接 QQ」选择「QQ 官方机器人」，填入 AppID 与 AppSecret 并保存；也可以在 `.env` 里设置 `QQBOT_APP_ID` 与 `QQBOT_APP_SECRET`（环境变量优先）。AppSecret 只会被保存，不会再回显给页面。
3. 连接页显示连接状态、机器人名和最近事件时间。群消息范围显示为「全部群消息」或「只有 @ 她的消息」；如果是后者，去开放平台开启「接收所有消息」。

会话键形如 `qqbot:<AppID>:group:<群 openid>`、`qqbot:<AppID>:private:<用户 openid>`。

### 官方通道里她如何行事

- **@ 与引用**：用平台给出的「是不是机器人」判断有没有被 @；引用内容取自事件里携带的消息元素，被引用的是她自己时，视为在回她。
- **回复与分条**：窗口内回复带上原消息编号，多个气泡依次递增序号；窗口外自动改发主动消息。投递结果不确定时不重发，这与 OneBot 一致。
- **主动联系与分享**：她想主动找人时，会先看对方是否关闭了主动消息；关闭了就不发，等对方来找她。单聊里每个周期可用一次唤醒作为兜底。
- **名字**：群名、单聊昵称拿不到时，先用已经知道的名字，再不行用「QQ 用户·末四位」占位。在「对话」里可以给任意会话改名，两种通道都可用。
- **身份**：官方平台上同一个人在不同群里的 openid 不同。像一个人只在不同房间见过对方，平台给出统一身份之前，她不会把这两处的人当成同一个人。这是有意为之，不是缺陷。
- **图片**：附件地址交给同一条视觉链路；官方通道不需要刷新目录。

## 切换时会发生什么

- 切换会断开当前连接；原来方式下的会话仍然可以查看，但不能再向它们发送消息。
- 记忆、关系、日记与自我不受影响，因为它们属于她，不属于通道。
- 两种方式的人物编号规则不同（QQ 号与 openid）。她对一个人的印象跟着编号走，换通道后同一个真人会显示为新的人。

## 开发者：新增一种通道

通道契约在 `server/channels/contract.js`：`type`、`capabilities`、`attach`、`start`、`stop`、`send`、`fetchQuoted`、`fetchImage`、`refreshDirectory`、`canReach`、`status`、`close`。新增通道只需要写一个目录实现契约，在 `server/channels/adapters.js` 注册适配器，并在 `server/channels/index.js` 的 `createChannels` 里加一行；核心以上不需要改动。步骤见 `docs/zh/architecture.md`。
