# 长期演进准则

请将 LuckyTri 视为一个需要长期迭代、持续成长的智能体系统，而不是一个功能逐渐增多的聊天机器人。

我们的终极目标，是让 LuckyTri 从被动响应的程序，逐渐发展为具有稳定人格、连续记忆、时间感知、自主判断、内在目标和长期行为一致性的智能体。

长期优化方向：
1. 更深入的理解：结合上下文、历史经历、人物关系与现实情境，把握真正的交流意图。
2. 更自然的表达：稳定、鲜明而灵活的个人风格；能幽默、表达不同意见，而非模板话术或机械迎合。
3. 更完整的记忆：从存储与检索发展为具有关联、时间顺序、因果关系、重要性和动态更新能力的长期经历系统；充分利用向量模型，让过去经历真正影响当前理解与决策。
4. 更连贯的内在世界：自我认知、偏好、目标、关系和情绪模拟相互影响，并随经历演化，而非每次对话重新开始。
5. 更有意义的自主性：主动关注问题、安排事项、回顾经历、形成目标并行动；有动机、有依据、有连续性，尊重用户意愿和权限边界。
6. 更真实的成长：根据新经历修正旧观点、改变偏好、重新理解过去、质疑既有判断；保持核心人格连续，但不永久锁定在初始人设。
7. 更完善的认知能力：记忆、推理、反思、规划、决策与行动协作；从经验总结规律、识别自身局限、改善未来行为。

长期工程原则：
- 不预先认定某种架构是最终答案；根据项目实际表现评估新技术价值。
- 优先优化基础能力和模块协作，而非盲目增加功能、Prompt 或模型调用。架构简洁、模块解耦、数据可靠，兼顾速度、Token 成本、隐私安全与可维护性。
- 建立持续评估机制（真实交互、长期记忆测试、行为一致性测试、用户反馈）。每次优化要有明确目标、可验证收益和回退能力。
- 不要把“更像人”误认为“更智能”，也不要把复杂行为表现误认为真正的意识。不靠预设大量规则塑造理想人格，而靠可靠的记忆、持续的经历、合理的认知机制和逐步开放的自主决策，让行为呈现自然、稳定、可解释的成长。
- 每次改动都要自问：是否真的让 LuckyTri 更接近这一目标？

最终：让她把经历连接起来，形成一段持续发展的历史；她不应该永远只是最初设计的模样。

## 怎样用这份准则

- 每次改动先写清楚它服务哪一条方向，以及怎样验证收益：`scripts/dev/` 下的评测（`evaluate-recall.js`、`evaluate-turn-cost.js`、`benchmark-recall-scale.js` 等）给出改动前后的对比，数字写进提交说明或报告。
- 没有可验证收益、或者只能靠加长 Prompt 才“看起来更好”的改动不合并；评测结果变差的改动回退。
- 心智表只追加、变化引用来源、撤销留墓碑（见[架构](architecture.md)），这是“成长可追溯、可回退”的基础，不为任何新机制破例。
