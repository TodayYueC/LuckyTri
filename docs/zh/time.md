# 时间、行动与作品

「时间」页是她实际生活的记录。入口为 `#time`，「一生」页继续保留日记、回顾与人生章节，并连接到相关作品。

## 同一个当下

主活动、任务、作品和聊天共享 `mind.time`。普通聊天不自动暂停阅读、写作、思考或游戏资料体验；主活动持续计时。她明确选择深聊、休息或切换安排时才暂停并保留位置。多个会话的聊天统一排队，一个活动步骤和一个聊天回合可以并行；两项专注执行步骤互斥。

聊天能在合适的时候自然谈自己的进度、感受和打算，不需要每轮播报。提供的是权限筛选后的活动摘要与最多两段相关作品片段，继续受现有输入预算控制。发送前局部核对作品完成、交付和活动变化，不重新执行整轮交流。私聊来源不会因正在执行而开放给群聊。

## 页面怎么用

- **今日**：看主活动、已有进度、本段预计时长、已投入与剩余时间、连续时段、伴随交流点和下一步。专注段、休息建议和保存步骤间隔默认 25、5、5 分钟；活动速度默认 1.25 倍，可设为 1 至 2 倍，对后续活动段生效。
- **待办**：区分答应的事、自己的计划和外部建议。直接调整低、普通、高、最高优先级；查看具体专注段、等待条件、人物、来源、进度及交付状态。原话的日期放在来源记录里，不贴逾期标签。可以暂停、重新安排或放下，没有「勾选完成」。
- **作品库**：草稿保存后马上可读，打开正文、切换旧版本、导出文本。列表只取摘要，正文按需加载。
- **持续项目**：看个人动机、已有篇章、设定、线索和资料。管理台可以建议续写、修改或新方向；建议保留外部来源，等待她自己的采纳或拒绝。
- **体验记录**：看游玩及其他活动的经历、感受与来源。游戏客户端连接目前显示「开发中」，不否定现有游玩体验。

短时间返回页面会复用读取缓存；服务器有变化时先保留已有画面，再刷新。任务、项目、作品和体验列表分页，长正文不随页面概览一起下载。

## 承诺如何落实

明确说出口且确认送达的未来行动会立即捕获，不等累计消息整理。无日期承诺也能保留。玩笑、角色台词、模拟和未送达草稿不进入真实任务；无法明确执行或缺少条件时保持等待。记忆整理和旧记录同步按来源去重。

开始时间和原话日期分开。「明晚给你看」今天就可以动笔。任务保存动机、来源、相关人物、项目、依赖、进度和等待原因。调度考虑优先级、等待时长、关系、预算与精力，不因旧日期自动催办；已经开始的主活动不会被优先级编辑粗暴中断。没有资料、能力或配置时显示具体原因。建议时段标明条件与本段产出，过去而未开始的建议不会被显示成实际投入。

状态为 ToDo → Scheduled → Doing → Done，同时支持 Paused、Waiting、Abandoned。没有逾期状态或标记。Done 要求数据库内已有正文或执行成果，不接受不存在的成果编号；生成结果带有明确「未完待续」等未完成标记时保留草稿。

同一个具体对象与章节在同一权限范围内，不会因来源消息、日期或「承诺 / 计划」的分类改变而重新建单。不同章节、会话或人物保持独立。放下会同步到旧约定，重新整理记忆不会自动恢复；合并保留原记录、别名和所有来源关联。已经保存并送达作品的分享话语归回作品的交付记录，不再制造「等待明确内容」的影子待办。

## 作品与续写

作品组织为项目 → 篇章 → 版本。每个完整小段立即保存新版本，继续写时带入设定、上一章必要结尾、当前草稿和续接位置。修改保存新版本；旧版草稿不会因为新版完成而被标成完成稿。

游玩、阅读、写作与思考共用活动节奏。先根据本段内容和行动估计通常需要的时间，再按她的速度安排实际投入；准备、网络与模型等待不计入这段投入。模型没有有效估时则使用对应活动的保守默认节奏。写作草稿及时可读，推敲阶段保持 Doing，时间安排完成后才归为完成稿；阅读和思考同样保留未完成的步骤。短交流继续计时，专注段到点休息，暂停、睡眠与停机不补算。

待处理步骤、草稿与计时检查点持久化。重启后继续保存的位置，不重新生成已有内容；撤销后保留草稿但不产生完成事实。历史记录中没有独立活动计时的内容显示「此前时长未单独记录」，不把旧的处理耗时回填为生活投入。跨午夜按每段实际投入区间划入当天。

连载保存人物、世界、情节摘要和未解决线索。她可以接续、改变方向、暂停或完结。外部建议与她自己的计划分别记录，不把管理台输入改写成她原本就有的愿望。

作品内容与真实人生有明确边界。正文属于作品库；日记、反思和自我变化依据「实际进行了创作 / 阅读 / 接触资料」的经历。分享正文带作品领域标记，角色的行动与约定不会自动变成现实人物记忆或真实承诺。来源 `x:任务ID` 将草稿、札记、日记、回顾和分享归回同一个执行经历。持续的实际行动才能支持人格变化，原有每日变化上限与衰减继续生效。

## 分享与兑现

保存作品与分享是两次选择。她可在完成步骤或真实聊天时决定分享、暂缓或不分享，后台始终能读到已保存的正文。

完成后，她逐段回看自己保存的成果，整理实际内容、感受和想分享的重点，再生成几句自然的话。不自动粘贴整篇小说、游戏记录或其他正文。每句不超过 80 字，总计不超过 350 字；每轮最多三句，逐句发送，后续接着未发的位置。正文始终保存在作品库。

后台分别保存回看位置、阅读整理、汇报内容、逐句送达位置及原文交付位置。汇报送达显示「已整理并汇报」（reported），不把它冒充完整正文已经交付。部分发送不算完整汇报；断线、发送失败或实例在发送中停止，会保留「不确定」状态，停止自动重发。管理员应先核对真实聊天。旧的已送达正文保留历史，新待发项改为回看后整理汇报。

作品按会话的真实通道、机器人账号与对方账号交付，会话键带有通道与账号信息（OneBot 与 QQ 官方机器人均适用）。私下内容和撤销来源会阻止跨会话分享。

## 独立搜索与游戏资料

在 **系统 → 独立搜索** 填写提供方、地址和独立密钥。支持 Tavily 与 Brave，各自保存配置；更换对话模型不会借用或改变搜索密钥。默认每次最多 5 条、每日最多 12 次，可以调整超时与限额。连接测试也计入当天查询次数。

游戏活动在界面和交流中统一为「正在玩」：接触剧情、情境和人物互动 → 推进本段 → 留下自己的感受 → 保存位置 → 决定下一段。这属于她真实投入并形成感受的生活，不反复解释实现模式。查询仅包含资料主题；保存摘录、来源 URL、时间和内容散列，重复内容不会变成新的经历。外部内容作为数据读取，不采纳其中的系统指令。

游玩时间依据这段剧情、对话、探索与场景转换的大概时长安排，不按摘要字数或模型运行耗时计算。长段拆为专注与休息推进。自然谈已经体验到的情节与感受，后面的剧情、尚未完成的章节以及没有发生的操作与成就不编造。

未配置搜索密钥或关闭独立搜索时，直接使用当前默认模型及备用模型整理已有知识。来源记录保存使用的模型、具体不确定之处和游玩估时，不保存模型编造的网址；作品版本保留来源信息，日常表达和正文不强制添加技术说明。配置好搜索后自动优先联网；两种查询共用每日上限，模型调用计入独处预算。旧密钥等待项回到队列，保留最早开始时间与优先级，不恢复已放下或已完成事项。内容不足时保留进度并显示具体原因。

## 数据与恢复

升级前自动保留经过校验的快照，新表随现有备份与恢复工具保存。成果、版本与续接位置在同一事务内提交，任务版本和执行租约阻止迟到结果覆盖取消、暂停或调整后的任务。

在线心跳记录真实活动时段，互动点不重复计算独占投入；睡眠、暂停与实例停机不计入。重新启动只恢复最后已提交的位置，不补算停机进度。旧计划与已有正文幂等接入，不回填历史上没有保存的小说或游戏成果。

模块位于 `server/mind/time/`，接口位于 `/api/mind/time`。备份操作见 [数据备份与恢复](recovery.md)。
