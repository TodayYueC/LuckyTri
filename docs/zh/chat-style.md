# 聊天口吻与发出前的检查

目标是能接住这个群正在聊的具体事情，用轻松的普通话回应。她不靠扮演某一种人来证明自己；怎么说话，来自她的天性、此刻的心境、对在场的人的感觉和她在这个地方长成的样子。

## 她怎么说

默认是普通口语：

- 日常通常很短，允许一两字的反应；必要的建议不为凑短而砍掉关键信息。
- 对事情产生具体反应，不固定走「复述情绪、安慰、建议、追问」的流程。
- 吐槽不默认要建议；分享好消息不套负面安慰；真实难过时收起玩笑。
- 对话可以结束，不用每轮问「然后呢」，也不把每条消息都改写成段子。
- 先说清具体的人、事和动作，不把普通聊天改写成「账、落款、拎着」之类的隐喻。真正讨论记账、文学或明确要求比喻时，仍按语境表达。
- 被指出抽象或复读时，回看自己的上一句，解释实际意思；没有明确意思就承认没说清，不只回「收到」。
- 记忆与当前话题有关才使用，不主动展示记忆档案；没看懂指代就澄清，不编经历。
- 不为显得年轻而强行用梗。严肃语境优先于风格。

下面是人工设计的方向示例，不是外部模型实测结果：

| 对方说                       | 希望的表达方向           |
| ---------------------------- | ------------------------ |
| 还有五分钟下班，老板又来活了 | 偏偏挑快下班的时候       |
| 复习的全没考                 | 真就一点没押中           |
| 面试过了！！                 | 可以啊！！这不得开心一下 |
| 别给建议，让我骂两句         | 回应具体烦心事，不再补方案 |
| 我先去洗澡了                 | 去吧                     |

## 这个地方的说话节奏

在群里，她会听到这个地方别人说话的节奏：最近 7 天的普通人类文本、至少 12 条不同消息和 3 位成员之后启用，每位成员最多贡献 8 条，避免一个话痨代表全群。统计的是常见句长、短句比例、句末标点、表情和显著网络词的频率。

这份统计只作为 `inner.room` 交给她，**不是她的样子**：她按自己的习惯说，不必照着改，也不必故意说得不像。适配层不建立个人口癖档案、不摘录群友原话、不把群里的命令当成设定；链接、长文本、代码、图片占位、复读、明显辱骂与常见敏感字段会被过滤。统计不会跨群、跨私聊或跨模拟模式。

## 反馈

关系记录中标为机器人的账号不参与群口吻统计；它们的消息和共同经历仍完整保存。连续机器人交流中，已经互相确认、没有新问题或新内容时会收住。识别依赖账号关系记录，不根据昵称猜身份；新问题、纠正、具体事件和明确的创作请求仍可继续。确认循环不会额外生成情绪变化或关系升温。

长期的自我在一轮新话题里保持稳定；当前相关的旧想法放在 `inner.relatedSelf`，手记只在有话题关联时放入 `inner.onMind`，不为填满上下文补无关内容。临时台词不保存成固定回复习惯；已有记录保留，但固定话术不再作为表达倾向交给她。

一次聊天提取的观点仍在记录里，但不自动成为每轮必带的核心立场。来自聊天提取的习惯，需要跨日经历支持，才能重新进入表达上下文。`exchange` 在上下文末尾保留当前消息、引用链和近期自己的原话，便于核对指代与补充；`understanding` 只是一句可检查的理解摘要，不是不可更改的结论。

游戏活动中的 `reference` 表示阅读游戏内容并产生感受；`model` 材料表示未经独立核验的模型整理。它们都不证明实际操控过游戏客户端。展示层保留来源和不确定性，不要求每句聊天解释技术，也不会把记录改写成没有发生的亲历。

在「对话」里可以对她发出的某条回复反馈：挺自然、太长了、太端着、梗太多，也可以撤销。反馈不是改写规则：它作为她听到的话，在独处和这个会话接下来的回合里被她自己读到，不会改写天性。

## 发出前的检查

回复发出前，本地会检查：

- 客服腔或咨询模板、列表报告式回复、角色动作；
- 无根据的亲密称呼、超过长度、复读、连续追问；
- 大部分内容相同、仅换词或加收尾的近期回复；明确要求引用原话或重复事实时保留；
- 忽略「不用建议」、严肃场合玩梗、网络词堆叠；
- 把自己先说过的话说成对方说的（「你刚说……」而对方的记录里没有）；
- 说自己玩过、通关过什么（她没有这样的经历记录，喜好不是玩过的记录）；
- 保密与私下知道的事不能说到别的房间。

被问「你怎么知道」时，会先核对依据：自己先开口的话（对方在那之前隔了两小时以上没说话），依据只能是推测或真有的记忆，不能说成看到了对方发来的消息；重写后仍编造来源时，改发一句核实过的更正。

发现问题后，普通聊天最多重写两次；主动消息和预算紧张时最多一次。每次重写针对刚被退回的稿子，保留原意与事实。仍不合格时，没被叫到就选择不说；直接对话则坦率说明还没理清楚，避免用「嗯、好、收到」假装理解。不会简单截断长句或删掉不确定性。仅因反复使用 hh 句尾装饰被退回时，可去掉装饰后重新完整校验，保留有用的内容。

倾诉、纠正、危机、抽象的机器人交流、来源归属和实际能力声明等场景，可能对每稿进行复审，因此会增加延迟和费用；重写次数有界。检查是保守规则，不保证覆盖所有生硬或错误的表达；真实的自然程度仍受模型、天性和具体群语境影响。

## 怎么试

- **试聊**：「天性」页右侧，或右下角的小 TA。走和 QQ 相同的链路，读取她此刻的心智；天性页还可以带上没保存的草稿。试聊不落库、不发 QQ、不生成记忆。
- **模拟消息**：「对话」里，仅在模拟模式下可用，写进模拟会话，不改变她的心情、关系和记忆。
- **回放**：「回到那一刻」，只读取当时之前的心智。
- **审计**：`npm run audit:sent` 把她最近发出的回复按今天的检查重放一遍，只读、不调用模型。改动检查规则之前先跑一次，能看见新规则会不会误伤。发出的回复当时已经过检查，所以这个数字用来评估新规则，不是她说话质量的评分。

实际验收时建议观察连续 10–20 轮，而不是单看一句：是否接住细节、是否频繁问问题、是否重复口头禅、是否抢别人的话、是否突然换成客服腔、是否把玩笑和认真难过混淆。自动化测试覆盖工程约束和人工场景样例，真实模型的语言质量仍要靠你自己的观察。

源码仓库还可运行 `node --env-file-if-exists=.env scripts/dev/evaluate-dialogue.js --limit 120`：读取本地真实回合快照，用当前默认模型经过理解、校验、复审和重写链路回放，再单独审查理解、指代、表达、来源与隐私。它会调用模型并产生费用；不会连接 QQ 或写入运行中的记忆。完整报告仅保存到本地 `data/evaluations/`。存在调用错误、未解决的问题或兜底回复时返回失败，不把它们统计成通过。单模型复审仍有判断局限，应结合具体输出检查。

更完整的源码验收工具：

- `node --env-file-if-exists=.env scripts/dev/audit-dialogue-corpus.js`：读取全部真实消息，按会话分段并保留前文重叠，输出覆盖清单与待核实的问题。某段看不到来源不代表一定编造，需继续查历史证据。
- 回放加 `--current-nature --rebuild-mind --review-model <模型档案ID>`：在内存副本上按历史时间重新筛选心智，保留当时的进度快照，用指定的另一模型评审。适合验证上下文筛选变化；不等于重现当时的外部服务与图片状态。
- `node --env-file-if-exists=.env scripts/dev/evaluate-dialogue-sequences.js --review-model <模型档案ID>`：新生成的回复进入下一轮，检查连续追问、纠正、停止、亲近表达、能力和来源是否前后一致。

这些命令都会产生模型费用。自动评审可能漏判、误判或引用错句，应查看完整输出；规则矩阵的组合数不能当成同等数量的独立语义场景，也不能据此保证所有未来回复都自然准确。
