# LuckyBot · 从零上手教程

LuckyBot 在本机思考和回复。NapCat 负责 QQ 登录与收发。模型 API 是单独的外部服务。QQ 扫码和安全确认在 QQ 或 NapCat 窗口完成。

## 1. 启动

需要 Node.js 24 或更高版本。在项目目录执行：

```powershell
node --version
npm install
npm start
```

打开 <http://127.0.0.1:3210>。终端里的 SQLite 实验性提示不表示启动失败，以能否打开 LuckyBot 为准。

Windows 日常使用可以双击 `启动LuckyBot.cmd`。服务已在运行时，它只打开 LuckyBot。关闭浏览器不会停止服务；停止时双击 `停止LuckyBot.cmd`，或在项目目录执行 `npm run stop`。这条命令只停止当前项目，不会结束其他 Node 进程。前台运行时也可以在该终端按 `Ctrl+C`。

LuckyBot 有五个入口：

| 入口 | 里面有什么 |
| --- | --- |
| 今日 | 运行状态、最近互动、全局参与和模拟模式 |
| 对话 | 现场、会话设置、历史回放 |
| 她 | 此刻、自我、关系、一生、天性，以及走真实链路的试聊 |
| 记忆 | 她记得的事、文档知识库 |
| 系统 | 模型配置、QQ 连接 |

## 2. 本机令牌

连接 QQ 之前先停止服务，再生成配置：

```powershell
npm run stop
npm run setup
```

没有 `.env` 时，setup 会写入管理令牌和 QQ 连接令牌。已有 `.env` 会原样保留。

```dotenv
HOST=127.0.0.1
PORT=3210
ADMIN_TOKEN=
ONEBOT_TOKEN=
LLM_API_KEY=
```

| 字段 | 用途 |
| --- | --- |
| ADMIN_TOKEN | 打开 LuckyBot 和调用 HTTP API；停止命令也会使用 |
| ONEBOT_TOKEN | NapCat 连接 `/onebot/v11/ws` |
| LLM_API_KEY | 可选；非空时优先于 LuckyBot 里保存的模型密钥 |
| HOST / PORT | 监听地址和端口；本机使用保持默认 |

页面第一次取数据时输入 `ADMIN_TOKEN`。令牌只留在当前标签页。修改 `.env` 后必须重启。不要把 `ADMIN_TOKEN` 填进 NapCat，也不要把 `ONEBOT_TOKEN` 当成管理台密码。

## 3. 先在模拟模式试聊

默认开启模拟模式，消息不会发到 QQ。

1. 打开「对话 → 会话设置」，添加一个群聊，填写测试群号和名称。
2. 打开「对话 → 现场」，选择这个会话。
3. 在试聊里输入一句普通消息并发送。
4. 查看消息和「为什么开口 / 为什么没出声」。

没有模型密钥时，模拟回复使用本地样例，不调用模型。有密钥后，同一条路径会走真实发言流程，但仍然不发 QQ。模拟消息不会改变她的心情、关系和记忆。

「她 → 天性」右侧的试聊也走真实链路：读取她此刻的心智，可以带上还没保存的天性草稿，但不写入任何东西，也不发 QQ。

## 4. 连接模型

打开「系统 → 模型」。

- API 地址填写服务商的兼容接口根路径。程序会自己拼接 `/chat/completions`，不要把完整路径再写一遍。
- 模型名称填写服务商接受的模型 ID。
- API Key 留空表示保留已保存的密钥。

预设只填入常见地址和模型名，以服务商控制台里的实际模型为准。发言决策和回复生成需要模型返回 JSON 对象。

保存后点「测试模型连接」。测试不携带群聊原文。更换地址、模型或密钥后需要重新测试。

也可以先保持模拟模式，在「她 → 天性」里和她试聊，确认她说话的样子后再让她参加真实 QQ。

## 5. 接入 QQ

打开「系统 → QQ 连接」。

1. 点「使用内置安装器」。本机已有 QQ 时使用内置 Shell 包准备 NapCat；没有检测到 QQ 时使用 Windows OneKey 包。需要新版本时再检查更新。
2. 选择 NapCat 根目录。
3. 点「生成连接配置」。已有配置会在原目录留下备份。
4. 点「启动 NapCat 并登录 QQ」，按窗口提示扫码。二维码也会写到 NapCat 目录的 `cache/qrcode.png`。

小号需要已经在目标群里。LuckyBot 不保存 QQ 密码。

只有接入助手无法识别目录时，才到 NapCat 的网络配置里新建 WebSocket 客户端：

| 项目 | 本机填写 |
| --- | --- |
| 协议 | OneBot 11 |
| WebSocket URL | `ws://127.0.0.1:3210/onebot/v11/ws` |
| Token | `.env` 里的 `ONEBOT_TOKEN` |
| 消息格式 | 数组 |
| 启用 | 开启并保存 |

这里的 `3210` 是 LuckyBot 的端口。NapCat 和 LuckyBot 不在同一台机器或放在容器里时，`127.0.0.1` 指向各自环境，需要另行改地址，并先配置 `ADMIN_TOKEN`。

QQ 已连接只表示传输通了。到目标群发一条消息后，会话会出现在「会话设置」，新发现的会话默认暂停参与。

## 6. 让它参与会话

1. 在「今日」确认全局参与开启，关闭模拟模式并保存。
2. 在「会话设置」对目标群点「开启参与」。
3. 在 QQ 里 @ 小号，或直接叫它的名字。
4. 回到「现场」查看消息和决策。

开不开口由她自己决定，没有参与概率和冷却。被点名、私聊、引用她或出现危机信号时，她一定会细看，然后选择回答、简短反应、说不想聊或不出声；她的理由会显示在「现场」和「她 → 此刻」。普通群消息只在她在意时细看——刚聊过、有人问大家、聊到她的兴趣、熟人在说话、攒了不少消息——其余只扫一眼，不调用模型，下次细看时一起读。觉得她太安静，可以在天性里提高「主动」。

她默认 02:00 睡、08:00 醒（在「她 → 天性」里修改或关闭）。睡着时被叫到，会等醒来再看。每分钟发言轮数限制仍然保留，用来避免短时间连续发言。

在模型里打开「图片理解」后，私聊、@ 或引用里的图片会先由本机读取，再交给模型看画面。主模型不能看图时，在会话设置里另选一个打开了图片理解的视觉兼容模型。没有打开图片理解的模型不会收到画面。

## 7. 她、记忆和知识

「她 → 天性」是唯一由你编写的部分：名字、性格、兴趣、边界、底线和作息，每次保存为新的一版。她的自我、在各群的样子、对每个人的感觉会从经历里长出来，在「自我」「关系」里可以看到每次变化的来源，觉得不对可以撤销；撤销过的内容之后不会被写回来。她独处、写日记、夜里整理、回顾和改写自传的记录，以及她在等的事（别人说的安排、她答应的事，可以撤销），都在「一生」。很久没被触及的线索会慢慢淡出，在「自我」里单独列出；它们没有被删除，被聊到时会重新想起。每日 Token 上限、后台份额、夜里整理和回顾间隔也在「天性」里设置。

「记忆」里先选择会话。

- 她对所有会话只有一份记忆：别处知道的事只在相关时想起；私聊里知道的标为「私下知道」，不当众说；被要求保密的只在原来的会话里。可以在每条记忆上调整分寸、锁定或撤销。
- 群友说「记住，我……」会直接成为她记得的事（密码、验证码之类不会记）。
- 文档放入集合后按当前会话的可见范围检索。群聊不会装入其他私聊集合。
- 清空「现场」里的上下文不会删除长期记忆。

## 8. 备份与停止

```powershell
npm run backup
npm run stop
npm start
```

备份写到 `data/backups/`。数据库里有聊天、记忆和保存在库中的密钥，按私密文件保管。`.env` 不在这份备份里。

恢复时先停止服务，把当前 `data/friend.db` 及同名 `-wal`、`-shm` 移开，再把选中的备份复制为 `data/friend.db`。设置了 `DB_PATH` 时操作该路径。不要把旧的 WAL 文件和恢复后的数据库放在一起。

## 9. 常见问题

| 现象 | 先检查 |
| --- | --- |
| 页面打不开 | Node 是否在运行，地址是否为 `127.0.0.1:3210` |
| 端口已被占用 | 先 `npm run stop`，不要结束所有 node 进程 |
| 令牌错误 | 使用 `ADMIN_TOKEN`；改 `.env` 后重启 |
| QQ 未连接 | NapCat 是否登录，URL、端口、路径和 `ONEBOT_TOKEN` 是否一致 |
| 连接成功但没有会话 | 在 QQ 再发一条新消息，消息格式是否为数组 |
| 群里不回复 | 全局开关、会话开关、模拟模式、密钥；「现场」里是「扫了一眼」还是她细看后选择了不出声 |
| @ 了也不回 | 她是否睡着了（「她 → 此刻」）、每分钟限速、今日 Token 是否用完、模型错误，或她自己的理由 |
| 模型 401 / 403 | 密钥和权限；环境变量密钥可能覆盖 LuckyBot 里保存的密钥 |
| 模型 404 | API 地址不要重复拼接 `/chat/completions`，核对模型 ID |
| 模型不返回 JSON | 换支持 JSON 对象输出的模型，先做连接测试 |
| 记忆没有出现 | 是否是明确的「记住，我……」，是否被撤销，分寸是否为「要她保密」而当前不在原来的会话 |

不要把 API 密钥、`.env` 或私聊原文发到公开位置。
