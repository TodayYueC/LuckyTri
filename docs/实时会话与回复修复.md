# 实时会话与回复修复

本次修复依据生产日志，而非仅看模拟器。

## 原因

- 新面板没有独立实时聊天区域，调试页要手动加载才开始刷新。
- 记忆存储原本带 session_id，但列表混合显示所有会话，无法清楚分群管理。
- 视觉层每轮加载历史中所有图片，额外图片预算导致模型调用前失败。
- 新消息无论来源都取消生成中的回复，活跃群容易持续取消。
- 记忆整理被 await 在聊天任务末尾，阻塞同会话下一轮。
- 私聊和明确 @ 也串行跑决策、生成、复审，成本和延迟不必要地放大。
- DeepSeek 的 none 原先未发送 thinking disabled，不等于真正关闭推理。
- 生产日志多次记录 DeepSeek HTTP 402。官方将其定义为余额不足：https://api-docs.deepseek.com/quick_start/error_codes/ 。这需要账户侧处理或更换可用模型，软件不能补足余额。

## 修改

- 群聊管理增加添加、移出面板和恢复显示。移出面板使用可恢复归档，不删除该会话的原文、记忆或决策日志。
- 归档会话现在可以单独永久删除；删除前会先取消排队中的回复，再清理该会话的消息、阶段、记忆和调试日志，避免自动发现的旧群长期占据面板。
- 发言判断改成两阶段：每批消息先由语境决策判断是否值得插话；值得回复时直接生成，不经过概率。只有判断为旁听时才按会话里的 0–1 参与概率抽样，抽中后强制生成一次回复。这样明确问题不会被概率挡掉，普通闲聊仍然保持克制。

- “实时会话”独立页面，按群聊/私聊查看最近消息与发言原因；SSE 更新，3 秒轮询兜底。调试页自动加载。
- 记忆页按会话筛选，新增、合并、阶段整理与会话选择同步。后端也按会话查询，避免前端筛选被全局结果上限截掉。
- 视觉只取当前批次和引用链图片，每轮最多四张；最终请求按实际输入预算裁剪可选历史，保留当前消息及引用。
- 明确私聊/@/引用自己走直接回应路径，保留人格和本地质检。非直接群聊仍走模型决策及配置的深度检查。原“回复前模型自检”用于复杂语境路径。
- 目标说话人的补充仍可取消旧稿，但原待答消息会携带到下一批。无关成员发言不再一律取消直接回复。
- 记忆整理后台运行，私聊限速与普通群插话分开。人工停用会话和配置修改仍阻止旧稿发送。
- DeepSeek none 显式关闭 thinking；HTTP 402 解释显示在页面提示和实时决策列表中。

## 验证

93 项自动化测试通过，补充了直接回复绕过概率、后台记忆不阻塞、视觉聚焦、预算裁剪和保留未答消息的回归测试。浏览器测试验证实时会话无需刷新收到新消息、记忆跨会话切换不混显、手机和桌面布局。切换服务后，使用现有私聊消息做真实 API 隔离回放成功：direct 路径，一次 generation 调用，总耗时约 1.3 秒；未向 QQ 发送测试消息。之前的 402 保留在历史日志中，但该次调用已恢复成功。此耗时是单次样本，不是延迟保证。
