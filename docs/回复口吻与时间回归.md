# 回复口吻与时间回归（2026-09-21）

本轮先检查真实聊天记录，再使用当前保存的模型、人设和会话模型配置进行隔离评测。早上 09:31 的“好困！”曾被回复为“这么晚还醒着呀”；此前连续出现“今天怎么这么累啊……”“调休还上了一整天啊……”等复述。纠正时间后又出现“刚醒脑子还没转过来”。这些作为失败案例，而不是供模型模仿的范文。

## 改动

- 上下文提供明确的本地日期、时段、每条消息的本地时间，以及聊天中断间隔。默认中国时区。线上使用处理时刻，历史回放使用当时消息时刻，不把今天的时间带入旧对话。
- 时间和近期表达统计放在上下文尾部；不会因为当前分钟改变而改写前面的稳定历史前缀。
- 原始人设继续保存在编辑器中。构建有效人设时，去掉已识别的口吻章节中的引用示例台词，保留性格描述及核心身份、兴趣。不是自动删除所有人设引用，也不是修改用户保存的数据。
- 分开处理纠错、简单确认、倾诉、不想听建议等沟通目的。纠错和确认一句收住；多气泡仍保留给确实需要补充的场景。
- 本地校验检查连续省略号、拖音空气泡、重复开头、白天误说深夜、虚构刚醒或上课等经历、低毒舌时责备群友，以及无意义的追加气泡。
- 自然的 `hh`、笑声开头仍可重复；检测的是反复给长句加 `hhh` 装饰，不强迫每次换新梗。
- 开启会话 `deepCheck` 时，倾诉、纠错和发泄场景也进入语义复审。仍最多重写一次。普通短聊不因此一律增加复审。复审可能增加 API 耗时和用量。

## 如何重跑真实模型评测

在项目目录运行：

```powershell
node scripts/evaluate-conversation.js
```

该命令会产生模型 API 用量。读取已保存配置和历史，复制到内存数据库；发送 QQ 的回调被设置为直接报错，没有 QQ 连接，也不修改生产记忆。覆盖连续倾诉、旧口吻干扰、早晚纠正、凌晨说困、早晚直接询问、多人补充、短笑声以及实际历史夜聊转早晨。

输出保存在 `data/evaluations/conversation-时间戳.json`，包括输入、最终回复、校验问题、生成和重写原文、调用耗时；不保存密钥或图片 URL。每一轮失败记录也保留，不能仅挑好看的回复作为结果。

自动退出成功仅代表技术链路成功、没有发送兜底短句，不代表自然程度自动合格。仍应逐条查看输出，特别注意连续几轮是否复述相同意思、是否擅自推断经历、是否为凑气泡多说一句。有限场景验收不保证开放群聊永远不出错。

本地回归：`npm test`。WebUI 回归：`npm run test:ui`。

## 本轮验收结果

最终完整一轮记录：`data/evaluations/conversation-1789955988944.json`。15 次真实模型回复，逐条检查：未出现早晚颠倒、连续省略号、人身挖苦或本地兜底。旧口吻历史诱发的一次省略号候选经校验重写后，最终版本不再包含省略号。109 项自动化测试通过，WebUI 冒烟测试及格式检查通过。

这些场景通过本轮验收；这不等于断言所有开放聊天都已达到真人水平。此前失败轮次及一次供应商网络中断的记录也保留在评测目录。
