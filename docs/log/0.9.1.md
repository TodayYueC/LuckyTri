# 0.9.1 对话语境优化记录

日期：2026-09-29

## 实例观察

- 同一人先把 `csn` 展开成一句夸张的打趣，随后发 `wtmcsn`；旧回复分别当成陌生缩写和需要严肃拒绝的话，忽略了连续消息中的解释。
- 有人连发图片、表情和新的生活话题。旧的选择性视觉会把被叫到消息附近最多三张图一起送去理解，容易把新图接到旧话题。
- QQ 图片表情带有画面地址和标签，却因表情标记被视觉链路排除；QQ 自带 face 的文字名称也没有进入模型语境。面对表情时，旧回复容易描述字面内容或解释笑点。
- 实例里已有“模型生成期间新消息到达则撤销旧稿”的保护；从生成完成到第一气泡发送之间仍缺少给连续补充留出的短暂观察时间。

## 改动

1. 图片表情（包括 image、mface、market_face、sticker）有可用画面时进入现有安全视觉链路；普通 face 的 QQ 名称留在附件摘要里。图像仍受域名、下载大小和图片格式校验约束。
2. 每张图携带消息编号、发送人、表情类型和 QQ 标签。选择性看图只取本条、明确引用或紧挨着的同一人图片，不再因邻近而多取几张。视觉观察只缓存画面事实，缓存键升级到 v2，避免旧的带话题推断描述跨场景复用。
3. 回合、回复和校验都明确区分表情反应、截图分享与新话题。只发表情时，过长的画面说明和逐字复述会触发重写。对于谐音、拼音首字母与反话，先依据同一人前后消息和接话判断；无法唯一确定时轻问或短接，不把熟人间夸张玩笑自动当成真实威胁。
4. 队列中的正常回复在第一气泡发送前多等 250 毫秒并复查相关新消息；若对方连发，撤销旧稿，保留原消息与补充消息，让下一轮一起组织。危机消息不增加这段等待；已经送出的气泡不重发。

## 验证

- 回归覆盖 QQ 表情名称、图片表情读取、跨话题选图、表情复述拦截和发送前补充消息重组。
- `npm test`：362 项通过；`npm run build:ui` 与 `npm run docs:build` 通过；本次改动文件的 Prettier 检查通过。
- 仓库级 `npm run format:check` 因 88 个未改动文件原有的格式差异报错，未在本版本中批量改动这些文件。

## 边界

谐音和缩写没有可靠的穷举词典，仍由模型结合上下文判断。看不到画面的 face 只提供 QQ 标签，不会虚构视觉细节。发送请求已经到达 QQ 接口后无法撤回，因此发送前重组只保证第一气泡提交前的语境。
