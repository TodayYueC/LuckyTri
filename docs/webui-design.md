# WebUI 设计与维护

## 设计目标

采用 P3 风格的构图语言：大字号章节编号、不对称版面、斜切选中条、星形与轨道装饰、方向明确的切页过渡。配色转换为浅绿、纸白与深绿，保留日常管理工具的可读性。装饰只出现在导航、页头、封面和空状态，不覆盖真实内容。

## 信息架构

| 一级入口 | 页面 / 区域                  | 唯一职责                                      |
| -------- | ---------------------------- | --------------------------------------------- |
| 今日     | 运行状态、近期互动、快捷入口 | 看当前状态和开始常用操作                      |
| 对话     | 现场                         | 左侧实时消息；右侧决策、反馈、模拟试聊三选一  |
| 对话     | 会话设置                     | 左侧搜索 / 选择会话；右侧编辑该会话的参与策略 |
| 对话     | 历史回放                     | 消息范围、决策记录、完整详情三栏              |
| 记忆     | 会话记忆、文档知识库、待审核 | 先选会话，再管理对应数据；总结固定在列表上方  |
| 人格     | 人格与表达、高级 Prompt      | 单一核心人设编辑入口，旁边直接试聊            |
| 系统     | 模型、QQ 连接                | 模型主从编辑器；连接分步操作和状态清单        |

保留已有 hash 路径与后端接口。旧的八个路由归入五个一级入口，不增加新的业务层或重复 API。删除默认模型的重复配置表单；人格保存和真实模型预览共用同一份核心人设文本。规则样例明确标明不读取自定义人格。

## 布局与滚动所有权

桌面采用固定视口工作台：侧栏、页头、二级导航、内容舞台、底栏。`min-height: 0` 必须贯穿 flex/grid 父层，滚动由最内层内容承接，不让记录数量改变页面高度。

- 现场：消息独立滚动；右侧三种功能互斥展示。反馈每页 6 条、正文三行摘要、内部滚动、底部分页。137 条长反馈也不能拉高页面。
- 模型 / 会话：左侧列表滚动，右侧表单滚动，保存按钮留在底部操作条。
- 记忆：总结默认三行，展开后仍有最大高度；记忆列表独立滚动，每次展示 20 条。新增记忆收进弹层。
- 人格：表单和试聊历史分别滚动；Prompt 使用大编辑器；保存按钮与试聊输入保持可达。
- 回放：消息、日志和原始详情各自滚动，避免长 JSON 撑开布局。
- 手机：导航变横向，分栏依次堆叠，各长内容面板仍有明确高度。页面高度由固定功能区数量决定，不随消息数量无限增长。

## 视觉规范

公共令牌在 `studio-web/src/styles.css`：纸白 `#f5f8ef`、浅绿 `#d1edba`、亮绿 `#bbef8c`、深绿 `#103a31`、正文 `#102f29`。中文使用系统无衬线字体；大号英文与章节数字仅用于视觉锚点。标题、正文、说明三级层次，面板通常保留 18–24px 内边距。

交互使用短距离位移、透明度、斜切揭幕；装饰轨道缓慢漂移。鼠标为细箭头并带星形反馈，文本输入保留原生文本光标。所有装饰 `pointer-events: none`，导航装饰限定在按钮内部。支持系统减少动画和持久化的手动开关；键盘焦点始终可见。

## 实现边界

继续使用 Vue 3 + Vite。`App.vue` 只负责壳层和导航，`pages` 负责对应页面交互，`plates` 维持现有请求接口，服务端保留聊天、记忆和模型规则。没有数据库迁移、没有引入设计系统依赖、没有改动 QQ 消息生成逻辑。

实时消息在用户已位于底部时跟随新消息；用户回看旧消息时保持位置。切换会话清空旧视图并校验异步结果所属会话。操作错误统一显示短暂提示，保存失败保留草稿。

## 验证与发布

- `npm run build:ui`：构建随项目发布的 `public/app`。
- `npm run test:ui`：独立临时数据库、模拟 OneBot，不向真实群发送；覆盖 1440 / 820 / 390 宽度、八个页面、会话增删与设置、模型保存、人格试聊、记忆隔离 / 批量删除、实时消息、回放消息及 137 条长反馈压力场景。
- `npm test`：现有服务端回归检查。
- 截图只保存在忽略的 `workspace/ui-review`，真实聊天截图和配置不得提交。

后续增加功能应优先扩展所属页面的页内区域，避免重新堆成并列大卡片或无边界长列表。
